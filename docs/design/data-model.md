# Data model

Status: draft 1 (2026-11-11). Normative for `apps/server/src/adapters/db/migrations/`,
`apps/client/src/adapters/rowstore/`, and `packages/contract/src/payloads.ts`.

Three layers of data:

1. **Server rows** (Postgres): auth material, wrapped keys, ciphertext blobs, membership, sync
   sequence numbers, object bookkeeping. No plaintext content.
2. **Client rows** (`RowStore`: SQLite on Android, IndexedDB on web): a cache of server rows plus
   the outbox and sync cursors. No plaintext content (D-37).
3. **Encrypted payloads**: JSON inside sealed blobs (`crypto.md` section 6). Only clients read
   them. Their Zod schemas live in `packages/contract/src/payloads.ts`.

## 1. Conventions

| Topic | Rule |
|---|---|
| Ids | `text`, 22 characters base64url (`crypto.md` section 3), generated by the client for users, collections, entries, media, objects; generated by the server (same format, `node:crypto.randomBytes(16)`) for sessions, invites, public links |
| Binary | `bytea`; API transport base64url without padding |
| Time | `timestamptz`, always UTC from the injected clock; never `now()` inside service queries except column defaults used only by migrations |
| Deletes | Hard delete plus tombstone rows where clients must learn about the removal (section 2.8) |
| Migrations | Kysely `Migrator`, one TypeScript file per migration in `apps/server/src/adapters/db/migrations/NNNN_name.ts`, never edited after merge (guidelines 4.4) |
| Postgres | Version 17 or newer (pinned in `infra/compose/docker-compose.yml`) |

Numbers in `CHECK` constraints mirror `packages/core/src/crypto/constants.ts` and server config
defaults; migrations are fixed history, so the literal values in them are allowed there.

## 2. Server schema (migration `0001_initial`)

### 2.1 users

```sql
CREATE TABLE users (
  id                       text PRIMARY KEY CHECK (id ~ '^[A-Za-z0-9_-]{22}$'),
  username                 text NOT NULL UNIQUE CHECK (username ~ '^[a-z0-9._-]{3,32}$'),
  role                     text NOT NULL CHECK (role IN ('admin', 'member')),
  status                   text NOT NULL CHECK (status IN ('active', 'pending_deletion')),
  login_key_hash           bytea NOT NULL CHECK (octet_length(login_key_hash) = 32),
  recovery_login_key_hash  bytea NOT NULL CHECK (octet_length(recovery_login_key_hash) = 32),
  kdf_salt                 bytea NOT NULL CHECK (octet_length(kdf_salt) = 16),
  kdf_ops_limit            integer NOT NULL CHECK (kdf_ops_limit >= 1),
  kdf_mem_limit_bytes      bigint NOT NULL CHECK (kdf_mem_limit_bytes >= 134217728),
  master_key_by_kek        bytea NOT NULL,
  master_key_by_recovery   bytea NOT NULL,
  recovery_key_by_master   bytea NOT NULL,
  public_key               bytea NOT NULL CHECK (octet_length(public_key) = 32),
  private_key_by_master    bytea NOT NULL,
  quota_bytes              bigint NULL CHECK (quota_bytes >= 0),
  used_bytes               bigint NOT NULL DEFAULT 0 CHECK (used_bytes >= 0),
  deletion_due_at          timestamptz NULL,
  created_at               timestamptz NOT NULL,
  updated_at               timestamptz NOT NULL,
  CHECK (kdf_mem_limit_bytes * kdf_ops_limit >= 4294967296),
  CHECK ((status = 'pending_deletion') = (deletion_due_at IS NOT NULL))
);
```

- `quota_bytes NULL` means the server default (`settings.storage.defaultQuotaBytes`).
- `used_bytes` is a derived counter (guidelines 7.4): sum of `objects.size_bytes` for the user in
  any state. It is increased **once**, when `POST /objects/presign` inserts the `pending` row
  (the reservation that makes the quota check race-free), never at confirm, and decreased only
  by the `collect-objects` job when the row is deleted. Rebuilt by the reconciliation job
  `reconcile-usage` (section 5).
- Sign-in is allowed for `status = 'pending_deletion'` so the user can cancel; authenticated
  routes other than session check, sign-out, `/users/me` and cancel answer
  `403 ACCOUNT_PENDING_DELETION` (`api.md` §4).

### 2.2 sessions

```sql
CREATE TABLE sessions (
  id            text PRIMARY KEY,
  user_id       text NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token_hash    bytea NOT NULL UNIQUE CHECK (octet_length(token_hash) = 32),
  device_label  text NOT NULL CHECK (char_length(device_label) BETWEEN 1 AND 64),
  created_at    timestamptz NOT NULL,
  last_used_at  timestamptz NOT NULL,
  expires_at    timestamptz NOT NULL
);
CREATE INDEX sessions_user_id_idx ON sessions (user_id);
CREATE INDEX sessions_expires_at_idx ON sessions (expires_at);
```

- Token: `kdk_s_` + base64url(32 random bytes). Stored as SHA-256. The prefix lets secret
  scanners recognize leaked tokens.
- Sliding expiry: each authenticated request sets `last_used_at` and
  `expires_at = now + settings.auth.sessionIdleDays`, at most once per
  `constants.SESSION_TOUCH_INTERVAL_MINUTES` to avoid a write per request.
- Revoke = delete the row.

### 2.3 invites

```sql
CREATE TABLE invites (
  id           text PRIMARY KEY,
  token_hash   bytea NOT NULL UNIQUE CHECK (octet_length(token_hash) = 32),
  created_by   text NULL REFERENCES users(id) ON DELETE SET NULL,
  role         text NOT NULL CHECK (role IN ('admin', 'member')),
  expires_at   timestamptz NOT NULL,
  redeemed_by  text NULL REFERENCES users(id) ON DELETE SET NULL,
  redeemed_at  timestamptz NULL,
  revoked_at   timestamptz NULL,
  created_at   timestamptz NOT NULL
);
```

- Token: `kdk_i_` + base64url(32 random bytes); the invite link is
  `https://<app host>/invite#<token>` (fragment, so it stays out of server logs).
- `created_by NULL` = created by the server CLI. Bootstrapping (D-27): the CLI command
  `create-invite --role admin` prints the first invite link; the admin then signs up in the app
  (sign-up must run on a client because keys are generated there).
- Sign-up policy (`signUpAllowed` in `apps/server/src/domain/auth-rules.ts`, pure, spec 04 §3.2): `signupMode = 'invite'`
  requires a valid, unredeemed, unrevoked, unexpired invite; `'open'` (later, D-27/D-41) accepts
  no invite and assigns role `member`.

### 2.4 collections

```sql
CREATE TABLE collections (
  id             text PRIMARY KEY CHECK (id ~ '^[A-Za-z0-9_-]{22}$'),
  owner_id       text NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  kind           text NOT NULL CHECK (kind IN ('home', 'shared', 'link')),
  key_by_owner   bytea NOT NULL,
  metadata_blob  bytea NOT NULL,
  last_seq       bigint NOT NULL DEFAULT 0 CHECK (last_seq >= 0),
  tombstones_pruned_through_seq bigint NOT NULL DEFAULT 0,
  created_at     timestamptz NOT NULL,
  updated_at     timestamptz NOT NULL,
  meta_updated_at timestamptz NOT NULL
);
CREATE UNIQUE INDEX collections_one_home_per_owner ON collections (owner_id) WHERE kind = 'home';
CREATE INDEX collections_owner_id_idx ON collections (owner_id);
```

- `key_by_owner`: for `home`/`shared`, the collection key wrapped by the owner's MK; for `link`,
  the link secret wrapped by the owner's MK (`crypto.md` 8.2).
- `last_seq`: per-collection change counter (section 3). Allocating a sequence number updates
  `updated_at` but not `meta_updated_at`; `meta_updated_at` changes only when `key_by_owner` or
  `metadata_blob` changes (it drives `GET /sync/state`, `api.md` §8). Deleting a `shared` or `link`
  collection is a hard delete; entries stay in the owner's home collection.

### 2.6 entries

```sql
CREATE TABLE entries (
  id             text PRIMARY KEY CHECK (id ~ '^[A-Za-z0-9_-]{22}$'),
  owner_id       text NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  purpose        text NOT NULL CHECK (purpose IN ('journal', 'link_copy')),
  revision       integer NOT NULL CHECK (revision >= 1),
  metadata_blob  bytea NOT NULL,
  trashed_at     timestamptz NULL,
  created_at     timestamptz NOT NULL,
  updated_at     timestamptz NOT NULL
);
CREATE INDEX entries_trash_purge_idx ON entries (trashed_at) WHERE trashed_at IS NOT NULL;
CREATE INDEX entries_owner_id_idx ON entries (owner_id);
```

- `revision`: optimistic concurrency for `metadata_blob` only. Metadata updates send
  `baseRevision`; the server accepts only if it equals `revision`, then increments (sync conflict
  rules in `docs/design/sync.md`). Trash, restore and permanent delete are unconditional and do
  **not** change `revision`; they bump the membership `seq` (section 3) so other devices learn
  about them.
- `purpose = 'link_copy'`: stripped copies created for public links (`crypto.md` 8.2, D-25);
  members only of `link` collections; never shown in the owner's gallery.
- `metadata_blob` max size: `settings.limits.maxEntryMetadataBytes` (checked in the service).

### 2.8 membership_tombstones

```sql
CREATE TABLE membership_tombstones (
  collection_id  text NOT NULL REFERENCES collections(id) ON DELETE CASCADE,
  entry_id       text NOT NULL,
  seq            bigint NOT NULL,
  removed_at     timestamptz NOT NULL,
  PRIMARY KEY (collection_id, seq)
);
```

- Written in the same transaction that deletes a membership or permanently deletes an entry.
- Pruned by the job `prune-tombstones` when older than `settings.sync.tombstoneRetentionDays`;
  the job raises `collections.tombstones_pruned_through_seq`. A client whose cursor is below that
  value gets `resyncRequired: true` and rebuilds the collection from seq 0.

### 2.10 objects

```sql
CREATE TABLE objects (
  id                   text PRIMARY KEY CHECK (id ~ '^[A-Za-z0-9_-]{22}$'),
  owner_id             text NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
  media_id             text NULL REFERENCES media(id) ON DELETE SET NULL,
  variant              text NOT NULL CHECK (variant IN ('original', 'thumbnail')),
  object_key           text NOT NULL UNIQUE,
  size_bytes           bigint NOT NULL CHECK (size_bytes >= 40),
  state                text NOT NULL CHECK (state IN ('pending', 'uploaded', 'deleting')),
  multipart_upload_id  text NULL,
  part_size_bytes      integer NULL,          -- added by migration 0002_objects_part_size (spec 05 §10c)
  created_at           timestamptz NOT NULL,
  uploaded_at          timestamptz NULL,
  delete_after         timestamptz NULL,
  CHECK ((state = 'deleting') = (delete_after IS NOT NULL))
);
CREATE UNIQUE INDEX objects_one_pending_per_variant ON objects (media_id, variant)
  WHERE state = 'pending';
CREATE UNIQUE INDEX objects_one_uploaded_per_variant ON objects (media_id, variant)
  WHERE state = 'uploaded';
CREATE INDEX objects_gc_idx ON objects (delete_after) WHERE state = 'deleting';
CREATE INDEX objects_pending_idx ON objects (created_at) WHERE state = 'pending';
CREATE INDEX objects_owner_id_idx ON objects (owner_id);
```

- `object_key` layout: `v1/<ownerId>/<objectId>` (no media id or variant in the key).
- `size_bytes` is the ciphertext size declared by the client (STREAM size formula, `crypto.md`
  7.1); after upload the server checks it with `HeadObject` and rejects a mismatch.
- `size_bytes >= 40`: the smallest STREAM object (24-byte header + one empty final chunk tag).
- Lifecycle: `pending` (presigned, quota reserved) -> `uploaded` (confirmed) -> `deleting`
  (replaced, media removed, entry purged, or account erased) -> row deleted by GC after the bucket
  delete succeeds. `ON DELETE RESTRICT` on `owner_id` forces account erase to clear objects first.
- Objects are immutable (D-34): replacing a variant creates a new `pending` row while the old
  one stays `uploaded` (the two partial unique indexes allow exactly one of each). When the new
  object is confirmed, the same transaction moves the old `uploaded` row to `deleting` and the
  new one to `uploaded`. A failed replacement leaves the old object untouched.
- A size mismatch at confirm moves the new row to `deleting` (its reservation is released by GC).

### 2.11 public_links (flag `public_links`, D-10)

```sql
CREATE TABLE public_links (
  id                 text PRIMARY KEY,
  collection_id      text NOT NULL UNIQUE REFERENCES collections(id) ON DELETE CASCADE,
  access_token_hash  bytea NOT NULL CHECK (octet_length(access_token_hash) = 32),
  expires_at         timestamptz NULL,
  max_views          integer NULL CHECK (max_views >= 1),
  view_count         integer NOT NULL DEFAULT 0 CHECK (view_count >= 0),
  created_at         timestamptz NOT NULL
);
```

- Expiry choices mirror 1Password (F-1P-03): 1 hour, 1 day, 7 days (default), 14 days, 30 days,
  never, plus "one view" (`max_views = 1`). Listed in `packages/core/src/domain/link-expiry.ts`.
- Revoke = delete the `link` collection (cascades the link row and memberships); its
  `link_copy` entries are permanently deleted and their objects moved to `deleting`.

## 3. Sequence numbers (why sync never skips a change)

A global sequence would let a transaction with a lower number commit after one with a higher
number; a client that already advanced past the higher number would miss the lower one. Therefore:

1. Every change visible in a collection's feed takes the next number from that collection's own
   counter **inside the same transaction**:
   `UPDATE collections SET last_seq = last_seq + 1, updated_at = $now WHERE id = $id RETURNING last_seq`.
2. The row lock taken by that `UPDATE` is held until commit, so numbers within one collection
   commit in order.
3. A change touching several collections (editing an entry that is in the home collection and a
   shared collection) locks the collections **in ascending id order** to avoid deadlocks, takes
   one number per collection, and writes it into each membership row's `seq`.

Changes that bump membership `seq`: entry metadata update, trash/restore, media added/removed,
object uploaded or replaced, membership added. Removals write a tombstone with a new number.

## 4. Client RowStore schema

One logical schema; Android maps it to SQLite tables, web to IndexedDB object stores with the
listed indexes. Version tracking: SQLite `PRAGMA user_version`; IndexedDB database version. Both
start at 1; migrations in `apps/client/src/adapters/rowstore/migrations.ts`.

| Table / store | Key | Columns | Indexes |
|---|---|---|---|
| `kv` | `key` | `value` (bytes or JSON) | — |
| `collections` | `id` | `kind`, `ownerId`, `ownerUsername`, `role` (`owner`/`viewer`), `keyMaterial` (wrap or sealed payload), `metadataBlob`, `metaUpdatedAt`, `serverLastSeq`, `cursorSeq` | — |
| `entries` | `id` | `ownerId`, `purpose`, `revision`, `metadataBlob`, `baseMetadataBlob`, `baseRevision`, `serverPendingBlob`, `serverPendingRevision`, `trashedAt`, `createdAt`, `updatedAt`, `localState` | `localState` |
| `memberships` | `[collectionId, entryId]` | `entryKeyWrap`, `seq` | `entryId` |
| `media` | `id` | `entryId`, `mediaKeyWrap` | `entryId` |
| `objects` | `id` | `mediaId`, `variant`, `sizeBytes`, `plaintextSize`, `localState` (`missing`/`present`/`unavailable`: the server answered 404 for the object, spec 14 §4), `uploadState` (`local`/`queued`/`uploading`/`uploaded`/`dead`; `uploaded` means confirmed on the server), `uploadJobId`, `lastAccessAt` | `mediaId`, `[localState, lastAccessAt]`, `uploadState` |
| `outbox` | `id` (auto-increment) | `kind`, `payload` (JSON of ids and ciphertext references), `state` (`queued` or `dead`, `sync.md` §6), `createdAt`, `attempts`, `nextAttemptAt`, `lastErrorCode` | `[state, nextAttemptAt]` |
| `pins` | `entryId` | `pinnedAt` | — |

- `entries.localState`: `synced`, `pending_create`, `pending_update` (metadata only; pending trash,
  restore and delete are tracked by their outbox items alone, spec 10). `baseMetadataBlob` + `baseRevision` hold the last version
  the server confirmed, used for three-way merge on conflict (`sync.md`).
- `kv` keys (in `apps/client/src/keys/storage-keys.ts`): `account.userId`, `account.username`,
  `account.kdfParams`, `account.masterKeyByKek`, `account.recoveryKeyByMaster`,
  `account.publicKey`, `account.privateKeyByMaster`, `account.recoveryConfirmed`,
  `account.homeCollectionId`, `account.role` (spec 19), `account.deletionDueAt` (07b),
  `device.storagePersisted`, `device.notificationPermissionAsked` (08),
  `settings.device` (JSON: auto-lock minutes, Wi-Fi-only uploads, original cache cap bytes,
  encrypt thumbnails on device, location for captures (D-55, default off)). Outside RowStore (it is per account and not open yet at start):
  the active account and the Android server URL (spec 07a §4.5, 07b §2).
- The session token is **not** in RowStore: Android keeps it in `expo-secure-store`; web keeps it
  in memory, or in `sessionStorage` when "keep me signed in" is off, `localStorage` when on
  (guidelines 9.1).
- Plaintext never enters RowStore. The outbox stores only ids and references to ciphertext rows
  and ciphertext files.

### 4.1 FileStore layout

| Path (relative to the app data root) | Content | Encrypted |
|---|---|---|
| `objects/<objectId>.kdks` | STREAM objects (originals, thumbnails) | yes |
| `thumbs-plain/<mediaId>.webp` | Android only, default (D-12) | no (app-private) |
| `tmp/` | plaintext during capture/import, decrypted video during playback | no; wiped at start, on lock, after use |

Storage roots per platform. Everything is per account: `<acct>` = first 16 hex characters of
`genericHash(accountKey)`, `accountKey` = `<serverHost>/<userId>` (spec 07a), so file and database
names contain no username and two accounts never share storage.

| Path group | Android root | Web root | Why that root |
|---|---|---|---|
| `objects/`, `thumbs-plain/` | `Paths.document/kodakiko/<acct>/` (expo-file-system) | OPFS `kodakiko/<acct>/` | Local copies the user expects to survive a low-storage purge; size-managed by the app (section 4.2), not by the OS |
| `tmp/` | `Paths.cache/kodakiko/<acct>/tmp/`; the **whole** `Paths.cache` directory is wiped at start, lock and sign-out because libraries also write plaintext there (spec 09 §4.1) | none (web keeps plaintext only in memory) | The OS may reclaim it at any time; holds plaintext only transiently |
| RowStore | SQLite file `kodakiko-<acct>.db` (expo-sqlite default directory) | IndexedDB database `kodakiko-<acct>` | Must survive cache clearing; it is the source of truth for sync state |

The roots come from `apps/client/src/keys/paths.ts` (one `paths` module per area, guidelines 4.2);
no path string appears anywhere else.

### 4.2 Local copies and eviction (D-09, D-12)

Web calls `navigator.storage.persist()` after sign-in so the browser does not evict OPFS and
IndexedDB under storage pressure; a refusal is shown once as a warning in settings.

- Thumbnails are never evicted, and each thumbnail has exactly **one** local copy:
  - Android default mode: the plain file `thumbs-plain/<mediaId>.webp`. The encrypted thumbnail
    object is kept in `objects/` only until it is uploaded, then deleted locally.
  - Android "Encrypt thumbnails on this device" mode and web: the encrypted object in `objects/`
    (Android) or OPFS (web); no plain file. Switching modes converts the existing cache in the
    background.
  - Footprint estimate for the settings screen: about 40 KB per media item (512 px WebP), so
    60,000 media items need about 2.4 GB.
- Originals: when the total size of `objects` rows with `variant = 'original'` and
  `localState = 'present'` exceeds `settings.device.originalCacheCapBytes`, delete the least
  recently accessed files first, skipping objects of pinned entries and objects not yet uploaded
  (`uploadState != 'uploaded'`).

## 5. Background jobs (server)

| Job | Interval (config) | Work | Idempotent because |
|---|---|---|---|
| `purge-trash` | hourly | entries with `trashed_at < now - trashDays`: permanently delete (tombstones, objects -> `deleting` with `delete_after = now + objectGraceDays`) | selects by time; deleting a deleted entry is a no-op |
| `collect-objects` | every 10 min | objects `deleting` with `delete_after < now`: `DeleteObject`, then delete row and subtract `used_bytes` in one transaction | bucket delete of a missing key succeeds |
| `abort-stale-uploads` | hourly | objects `pending` older than `pendingUploadHours`: abort multipart if any, move to `deleting` | state check before update |
| `erase-accounts` | hourly | users `pending_deletion` with `deletion_due_at < now`: move all objects to `deleting` (`delete_after = now`), delete sessions; when no objects remain, delete the user row | resumable step by step |
| `prune-tombstones` | daily | delete tombstones older than retention; raise `tombstones_pruned_through_seq` | monotonic |
| `expire-sessions` | daily | delete sessions with `expires_at < now` | time-based |
| `reconcile-usage` | daily | recompute `used_bytes` from `objects`; log differences as `usage.reconciled` | recomputation |

Each job runs only if `pg_try_advisory_lock(<job lock id>)` succeeds (lock ids in
`apps/server/src/jobs/keys.ts`), processes at most `jobBatchSize` rows per run, has a timeout,
and logs `job.started` / `job.finished` / `job.failed` with counts.

## 6. Encrypted payload schemas (`packages/contract/src/payloads.ts`)

### 6.1 EntryMetadata v1

```ts
export const MediaDescriptorV1 = z.object({
  mediaId: idSchema,
  kind: z.enum(['photo', 'video']),
  mimeType: z.string().max(MIME_TYPE_MAX_CHARS),
  width: z.number().int().positive(),
  height: z.number().int().positive(),
  durationMs: z.number().int().nonnegative().nullable(),
  originalPlaintextBytes: z.number().int().nonnegative(),
  thumbnail: z.object({
    width: z.number().int().positive(),
    height: z.number().int().positive(),
    mimeType: z.literal('image/webp'),
    plaintextBytes: z.number().int().positive(),
  }),
  capturedAtUtc: z.iso.datetime().nullable(),
  originalFileName: z.string().max(FILE_NAME_MAX_CHARS).nullable(),
});

export const EntryMetadataV1 = z.object({
  schemaVersion: z.literal(1),
  takenAtUtc: z.iso.datetime(),
  utcOffsetMinutes: z.number().int().min(UTC_OFFSET_MINUTES_MIN).max(UTC_OFFSET_MINUTES_MAX),
  timeZone: z.string().max(TIME_ZONE_MAX_CHARS).nullable(),
  note: z.string().max(NOTE_MAX_CHARS),
  tags: z.array(TagName).max(TAGS_PER_ENTRY_MAX),
  location: z.object({
    latitude: z.number().min(LATITUDE_MIN).max(LATITUDE_MAX),
    longitude: z.number().min(LONGITUDE_MIN).max(LONGITUDE_MAX),
    accuracyMeters: z.number().nonnegative().nullable(),
    source: z.enum(['exif', 'device']),
  }).nullable(),
  media: z.array(MediaDescriptorV1).min(1).max(MEDIA_PER_ENTRY_HARD_MAX),
  createdAtUtc: z.iso.datetime(),
  editedAtUtc: z.iso.datetime(),
});
```

- Day grouping (D-14, D-21): the entry's local date is `takenAtUtc + utcOffsetMinutes`, so a
  moment stays on the day it happened even when viewed in another time zone. Pure function
  `localDateOf(takenAtUtc, utcOffsetMinutes)` in `packages/core/src/domain/entry-time.ts` (spec 10 §1).
- Array order of `media` is display order; index 0 is the cover in the gallery.
- An entry must have at least one media item (a moment is a snap); text-only entries are not in
  scope (not requested).
- Constants live in `packages/contract/src/limits.ts` (spec 03 §1; contract cannot import core):
  `NOTE_MAX_CHARS = 100_000`, `TAGS_PER_ENTRY_MAX = 50`, `TAG_MAX_CHARS = 64`,
  `MEDIA_PER_ENTRY_HARD_MAX = 100` (the configurable server limit, default 20, must not exceed it),
  `UTC_OFFSET_MINUTES_MIN/MAX = -840/840`, `TIME_ZONE_MAX_CHARS = 64`, `MIME_TYPE_MAX_CHARS = 100`,
  `FILE_NAME_MAX_CHARS = 255`, `LATITUDE_MIN/MAX = -90/90`, `LONGITUDE_MIN/MAX = -180/180`.
- Declaration order matters (the schemas are values): `TagName`, then `MediaDescriptorV1`, then
  `EntryMetadataV1`.

### 6.2 Tags (D-16)

`TagName` = string after normalization by `normalizeTag` (`packages/core/src/domain/tags.ts`):
NFKC -> trim -> collapse whitespace runs to one space -> lowercase (`toLocaleLowerCase('und')`
is not used; plain `toLowerCase()` for determinism) -> reject if empty or longer than
`TAG_MAX_CHARS`. Tags in an entry are unique after normalization and stored sorted.

### 6.4 Reserved

`userSettings` and `indexSnapshot` AD contexts (`crypto.md` section 3) are reserved and unused in
v1. Device settings stay local (`kv.settings.device`). The index is rebuilt on unlock by
decrypting rows (2 AEAD operations per entry: entry key unwrap and metadata open); an encrypted
snapshot is added only if measured unlock time on a mid-range Android phone exceeds
`constants.UNLOCK_BUDGET_MS` with 20,000 entries.
