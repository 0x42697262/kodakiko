# 01 — Monorepo scaffolding and tooling

Status: draft 2 (2026-11-11, after review 1).

Goal: an installable, verifiable pnpm monorepo with the four packages, strict TypeScript, the lint
rules from the guidelines (no comments, no magic numbers), and the pnpm supply-chain policy (D-11).
After this spec, `pnpm verify` passes on skeletons.

Read first: `docs/engineering-guidelines.md` §§3-5, 13.1, 15; `docs/dependencies.md` (all of it);
`docs/architecture.md` §3-4.

### 1.2 Lint configuration

`eslint.config.js` (ESM):

1. `ignores`: `**/node_modules/**`, `**/dist/**`, `**/.expo/**`, `**/coverage/**`,
   `apps/client/android/**`, `apps/client/ios/**`, `apps/client/expo-env.d.ts` (generated by Expo,
   contains comments), `apps/client/public/workers/**` and `apps/client/public/media-sw.js` (build output), `docs/**`.
2. `...tseslint.configs.recommended` (from `typescript-eslint`).
3. For all `**/*.{ts,tsx,js}`: plugin `kodakiko` from `tools/eslint-local/index.js`; rules
   - `kodakiko/no-comments`: `error`
   - `@typescript-eslint/no-unused-vars`: `['error', { argsIgnorePattern: '^_', varsIgnorePattern: '^_' }]`
   - `no-debugger`: `error`
4. For `{apps,packages}/*/src/**/*.{ts,tsx}` except files named `constants.ts`, `*-constants.ts`,
   `**/migrations/**`, `**/*.test.ts`: `@typescript-eslint/no-magic-numbers` = `['error', {
   ignore: [0, 1], ignoreArrayIndexes: true, ignoreEnums: true, ignoreNumericLiteralTypes: true,
   ignoreReadonlyClassProperties: true, ignoreTypeIndexes: true }]` (guidelines 4.2: numbers live
   in constants modules; bit masks and shifts included).
5. Import boundaries (architecture.md §3), `no-restricted-imports` per directory:
   - `packages/contract/**`: only `zod` and relative paths (patterns forbidding `@kodakiko/*`,
     `react*`, `expo*`, `node:*`);
   - `packages/core/src/**`: forbid `react`, `react-native`, `react-native-*`, `expo`, `expo-*`,
     `node:*`, `libsodium*`, `@kodakiko/server`, `@kodakiko/client`;
   - `apps/client/**`: forbid `@kodakiko/server`;
   - `apps/server/**`: forbid `@kodakiko/client`, `react*`, `expo*`.
   Literal strings are not lint-enforced (no reliable rule); their placement in catalogs is a review
   item (guidelines 4.2).

`tools/eslint-local/no-comments.js` exports `{ meta: { type: 'problem', messages: { noComments:
'Explanatory comments are forbidden; write docs/ instead (guidelines 4.1)' }, schema: [] },
create(context) { ... } }`. In `Program:exit` it reads `context.sourceCode.getAllComments()` and
reports every comment whose trimmed text does **not** start with one of: `eslint-disable`,
`eslint-enable`, `@ts-expect-error`. Block comments starting with `*` followed by `@license` are
also allowed (guidelines 4.1 exceptions).

### 1.3 Packages

For each package directory below create `package.json`, `tsconfig.json`, `vitest.config.ts` and
the listed source files.

| Package | Dir | Runtime dependencies now | Source files now |
|---|---|---|---|
| `@kodakiko/contract` | `packages/contract` | `zod: catalog:` | `src/ids.ts`, `src/bytes.ts`, `src/index.ts` (re-exports both), `test/bytes.test.ts` |
| `@kodakiko/core` | `packages/core` | `@kodakiko/contract: workspace:*`, `zod: catalog:`; devDependency `libsodium-wrappers-sumo: catalog:` | `src/index.ts` = `export {};` |
| `@kodakiko/server` | `apps/server` | none yet | `src/main.ts` = `export {};` |
| `@kodakiko/client` | `apps/client` | `expo`, `react`, `react-native`: all `catalog:` | `App.tsx` (default export a component returning `null`) |

Every `package.json`: `private: true`, `type: "module"`, script `test` = `vitest run
--passWithNoTests`. (`noEmit` comes from the base config, so `tsc` only checks.)

Package entry points (TypeScript sources are consumed directly by esbuild, Metro and vitest; no
build step for library packages):

| Package | `exports` |
|---|---|
| `@kodakiko/contract` | `{ ".": "./src/index.ts" }` |
| `@kodakiko/core` | `{ ".": "./src/index.ts", "./vectors": "./vectors/index.ts" }` |
| `@kodakiko/server` | `{ "./testing": "./src/testing.ts" }` (spec 08's e2e package uses it; `src/testing.ts` is created in spec 03 and re-exports `buildApp`, `loadSettings`, `createDatabase`, `migrateToLatest`) |
| `@kodakiko/client` | `{ "./testing": "./src/testing.ts", "./test-support": "./test/support/index.ts" }` (`./testing` added in spec 07b, `./test-support` in spec 08) |

TypeScript 6 defaults `types` to `[]` (no ambient Node types). Each library package therefore has
**two** tsconfig files, so `src/` stays free of Node globals while tests and scripts get them:

- `tsconfig.json` (src only): `{ "extends": "../../tsconfig.base.json", "include": ["src"] }`;
  server adds `"compilerOptions": { "types": ["node"] }`.
- `tsconfig.tools.json`: `{ "extends": "./tsconfig.json", "compilerOptions": { "types": ["node"] },
  "include": ["src", "test", "scripts", "vectors"] }`.
- script `typecheck` = `tsc -p tsconfig.json && tsc -p tsconfig.tools.json`.
- `@types/node` (`catalog:`) is a devDependency of contract, core and server.

Client `tsconfig.json` (single file): `{ "extends": ["expo/tsconfig.base", "../../tsconfig.base.json"], "compilerOptions":
  { "jsx": "react-jsx", "lib": ["ES2023", "DOM", "DOM.Iterable"] }, "include": ["**/*.ts",
  "**/*.tsx"] }`. The base config is listed second so its strict flags win. Client script
  `typecheck` = `tsc -p .`.

`vitest.config.ts`: `defineConfig({ test: { environment: 'node', include: ['test/**/*.test.ts',
'src/**/*.test.ts'] } })`.

Import specifiers: inside `packages/*` and `apps/server`, relative imports end in `.ts`
(`import { x } from './ids.ts'`), so Node can run scripts directly. Inside `apps/client`,
imports are extensionless so Metro can pick `*.native.ts` / `*.web.ts` (spec 07a).

### 1.4 `packages/contract/src/ids.ts` and `bytes.ts`

Every later spec imports these, so they are written now:

```ts
export const ID_PATTERN = '^[A-Za-z0-9_-]{22}$';
export const ID_REGEX = new RegExp(ID_PATTERN);
export const idSchema = z.string().regex(ID_REGEX).brand<'Id'>();
export type Id = z.infer<typeof idSchema>;

export const BASE64URL_REGEX = /^[A-Za-z0-9_-]+$/;
export const bytesSchema = z.string().min(1).regex(BASE64URL_REGEX).refine(isDecodableBase64Url).brand<'Bytes'>();
export type Bytes = z.infer<typeof bytesSchema>;
```

`bytes.ts` exports:

```ts
export function isDecodableBase64Url(value: string): boolean;
export function encodeBytes(bytes: Uint8Array): Bytes;
export function decodeBytes(value: Bytes): Uint8Array;
```

- Encoding: standard base64 alphabet with `+`→`-`, `/`→`_`, no `=` padding (RFC 4648 §5).
  Implement with a 64-character alphabet constant and bit operations, not `Buffer` or `atob`
  (the package must run in Node, React Native and browsers).
- `isDecodableBase64Url`: true when the regex matches and `value.length % 4 !== 1`.
- `decodeBytes` throws `RangeError` for non-decodable input (callers validate with the schema
  first).
- The alphabet, the group sizes (3 bytes / 4 characters, 6 and 8 bit widths) go in
  `packages/contract/src/constants.ts` (the magic-number rule applies).

`test/bytes.test.ts`: `encodeBytes(Uint8Array.of(0xfb, 0xff)) === '-_8'`; round-trip of lengths
0..64 with deterministic content; `isDecodableBase64Url('A') === false`; `'A+B'` fails
`bytesSchema`; a valid 22-char id passes `idSchema`, a 21-char one fails.

## 2. Steps

1. `corepack enable` (once per machine), then create all files of section 1.
2. `pnpm install`. If it stops with `ERR_PNPM_IGNORED_BUILDS`, follow the `allowBuilds` rule in
   `docs/dependencies.md` §"Policy settings"; anything not on the allowlist → stop and ask.
3. `pnpm --filter @kodakiko/client exec expo install --check`. Patch-level mismatches caused by
   the 7-day rule are expected (dependencies.md §"Version rule"): list them in the report.
   Minor/major mismatches → stop and ask.
4. `pnpm typecheck`, `pnpm lint`, `pnpm test`.
5. Negative tests of the lint rules:
   - add `// hello` as the first line of `packages/core/src/index.ts` → `pnpm lint` reports exactly
     one `kodakiko/no-comments` error; remove it;
   - add `export function sample(): number { return 42; }` to `packages/core/src/index.ts` → one
     `@typescript-eslint/no-magic-numbers` error; remove it. (The rule does not flag a number that
     directly initializes a `const`: `const LIMIT = 42` is a named value. Placing named values in
     constants modules is enforced by review, guidelines 4.2.)
   - `pnpm lint` passes again.
6. `pnpm verify`.

## 3. Verification checklist

- [ ] `pnpm install` exits 0; report any `allowBuilds` lines added.
- [ ] `expo install --check` output reported (expected patch-level warnings only).
- [ ] `pnpm verify` exits 0.
- [ ] Both lint negative tests failed as described, then passed after removal (paste both error
      lines).
- [ ] `pnpm-workspace.yaml` policy block equals `docs/dependencies.md` verbatim; catalog versions
      equal the allowlist (report any difference).
- [ ] `packages/contract` tests pass, including `'-_8'`.
- [ ] `pnpm-lock.yaml` is created and committed; no `node_modules`, `.expo` or build output tracked.

## 4. Done when

Checklist fully reported and `pnpm verify` green.
